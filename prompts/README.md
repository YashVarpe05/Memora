# prompts/

Implementation plans, written before the code and committed with it.

One file per task, `<short-name>.md`. Committed on purpose — a plan that
disappears into a chat window can't be reviewed by the other three, and
can't be pointed at later when someone asks why something was built.

Every plan states: goal in one sentence · what was read · assumptions
resolved without asking · files that will change · implementation
requirements · security requirements · acceptance criteria · checks to
run · exact steps to verify.

If a section is thin, push back before approving. The assumptions section
is the one worth reading closely — it's where a wrong guess is still cheap.
